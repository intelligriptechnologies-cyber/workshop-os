# WorkshopOS production vertical

This directory is the production architecture seam. It does not replace or import the browser-local demo.

- `src/local-production-vertical.ts` is the deterministic local/test adapter for PWA → `/api/v1` → tenant store/outbox → worker/private object → safe logs.
- `src/identity-access.ts` is the deterministic Cognito-compatible identity/provisioning adapter used to verify individual membership, branch/granular permission scope, kiosk sessions, MFA/re-authentication, maker-checker, support grants, and audit evidence without contacting Cognito.
- `src/versioned-configuration.ts` exposes the deterministic local `/api/v1` contract for tenant/branch-scoped master drafts, effective publication, immutable active-scope snapshots, exact money/UOM values, and fiscal document allocation.
- `src/lifecycle-command-engine.ts` centralizes stable lifecycle transitions, actionable blockers, optimistic concurrency, idempotent replay, cancellation/reopening, recent re-authentication, maker-checker approvals, and override evidence.
- `src/customer-vehicle-history.ts` exposes tenant/branch-scoped customer and vehicle identity, duplicate signals, versioned updates, append-only odometer/service/ownership history, and authorized merge compensation.
- `src/appointment-capacity.ts` exposes versioned/idempotent appointment commands, reasoned status history, closure/resource/skill/buffer-aware availability, controlled overbooking, and the durable S07 reception handoff event.
- `src/reception-custody-offline.ts` consumes that event or a walk-in into one atomic Visit/draft Job contract, validates versioned private custody evidence and acknowledgement, creates independent custody-incident notification cases, and keeps PWA offline state visibly draft-only with explicit conflict recovery.
- `src/advisor-inspection.ts` turns S07 draft Jobs into accountable advisor/action queues, controls audited reassignment, records configured structured/free-text inspection and private evidence, filters customer/internal notes by permission, manages due follow-ups and promised-delivery risk, and emits only the durable recommended-scope handoff owned by S09.
- `src/estimate-approval.ts` creates exact payer-aware immutable estimate versions, digest-only single-use public decisions, maker-checker manual fallback, supplementary scope, six-part configuration snapshots, and exactly-once work/material activation events.
- `src/action-notifications.ts` consumes tenant-scoped domain events once into role/owner action queues and a durable consent-aware notification outbox, using inert deterministic in-app/push/WhatsApp/SMS adapters with retry, provider status, dead-letter, fallback, and replay evidence.
- `src/job-planning-timeline.ts` consumes S09 approved-scope events exactly once into exact-snapshot DAG work plans, controls optimistic/idempotent multi-technician responsibility with explicit capacity warnings, exposes a permission-redacted shared Job chronology, and emits only the S12 task-assignment boundary.
- `src/technician-execution.ts` consumes that versioned assignment boundary exactly once into assignee-scoped large-touch My Tasks, controls elapsed and audited task progression/handoff, enforces snapshotted clean private evidence before completion, validates camera/hardware/manual scans, and provides durable conflict-safe non-ledger drafts with hard offline posting exclusions.
- `src/inventory-ledger.ts` provides warehouse/bin-authorized exact item/UOM/lot/serial/roll stock, reasoned FEFO, remnant/scrap lineage, append-only balanced quantity/value movements, evidence-controlled in-transit transfers, and frozen blind counts with recount, investigation, maker-checker compensation, and concurrent overspend rejection. Job material flow remains an S15 boundary.
- `src/procurement-workflow.ts` provides controlled supplier identity, contacts/tax/terms/addresses/item relations, versioned requisition and PO lines/approvals/partials, exact GST and landed-cost allocation, inspected evidenced GRNs that call S13 once, and independently authorized compensating purchase returns.
- `src/job-material-control.ts` turns approved Job/task demand into exact partial Store issues, independently approved substitutions and non-Job reasons, evidenced technician outcomes, Store-verified returns, controlled variance, and an exact reconciliation event consumed by QC and billing.
- `src/qc-rework.ts` requires separate task-completion and material-reconciliation readiness, records independent snapshotted item QC with clean evidence, controls blocking rework assignment/execution/reinspection, and emits unique passed or audited emergency-override release signals.
- `src/warranty-incidents.ts` exposes immutable delivered-Job warranty terms, creates classified linked comeback Visit/Job records without reopening finance, resolves evidenced custody incidents, and blocks record/media retention while an independently releasable legal hold is active.
- `src/native-invoicing.ts` gates native billing on explicit tenant authority and upstream scope/work/material/QC readiness, calculates exact snapshotted India GST per payer, atomically finalizes immutable fiscal documents, and records maker-checker credit/debit/cancel-reissue compensations plus private document/downstream events.
- `src/tally-connector.ts` is the inert Tally-authoritative `/api/v1` adapter: it creates one payer/Job exchange without a native invoice, validates duplicate-safe direct or controlled-file acknowledgements, exposes retained status/errors and amount/tax/payer/posting mismatches, and models bounded retry/dead-letter/replay without contacting Tally or writing exchange files externally.
- `src/payments-settlements.ts` provides exact advance/split-payment allocation, inert Cashfree link and signed-webhook authority, formal credit, maker-checker corrections, and settlement reconciliation without provider or banking side effects.
- `src/delivery-gate.ts` evaluates plain-language cross-domain closure readiness, controls evidenced maker-checker overrides, renders private versioned document artifacts with minimum-data QR verification, records delivery evidence, and permits only independent live gate verification to atomically close the journey.
- `src/management-reporting.ts` exposes permission-guided role boards, eight defined exact as-of report families with protected drill-through, and inert private manifest/checksum-backed asynchronous exports with expiry, revocation, and audit.
- `db/migrations/001_tenant_vertical.sql` is the PostgreSQL contract. A request transaction must set `app.tenant_id` and `app.branch_ids` from verified membership before querying; client tenant fields are never used for session context.
- `db/migrations/002_identity_access.sql` adds the tenant-keyed identity and control model, forces RLS, stores only kiosk PIN digests, and expands critical-action audit context.
- `db/migrations/003_versioned_configuration.sql` persists immutable effective master versions and scope snapshots, exact conversion ratios, and atomic tenant/branch/type/financial-year sequences under forced RLS.
- `db/migrations/004_lifecycle_command_engine.sql` persists versioned lifecycle resources plus append-only history/audit, maker-checker approvals, and tenant-scoped idempotency records under forced RLS.
- `db/migrations/005_customer_vehicle_history.sql` persists customer contacts/payer relations, vehicle identity and effective ownership/service snapshots, aliases, controlled merge/compensation, audit, and idempotency under forced RLS.
- `db/migrations/006_appointment_capacity.sql` persists appointments, capacity resources/closures, immutable schedule reservations/history/reception events/audit, serialized overlap enforcement, overbooking evidence, idempotency, and forced RLS.
- `db/migrations/007_reception_custody_offline.sql` persists atomic reception Visit/draft Job creation, single-use appointment-event consumption, private evidence/acknowledgement metadata, independent custody incidents/actions/notification outbox, append-only ledgers, idempotency, and forced RLS.
- `db/migrations/008_advisor_inspection.sql` guarantees one accountable advisor/action row per S07 Job, atomically moves ownership and queues, persists configured inspections/private clean evidence/recommended scope/S09 handoffs, follow-ups, promised-delivery history, audit/idempotency, append-only ledgers, and forced tenant/branch RLS.
- `db/migrations/009_estimate_approval.sql` persists versioned estimates/lines/payer allocations, digest-only public tokens, manual and public evidence, immutable scope activation, unique outbox effects, idempotency, and forced tenant/branch RLS.
- `db/migrations/010_action_inbox_notifications.sql` persists role/owner actions, immutable templates/events/preferences/attempts/provider evidence, unique notification effects, retry/dead-letter state, and concurrency-safe worker claiming under forced tenant/branch RLS.
- `db/migrations/011_job_planning_timeline.sql` persists exact planning snapshots, tasks/dependencies, responsibility history, shared timeline, command receipts, and S12 outbox effects with DAG/responsibility constraints, append-only evidence, and forced tenant/branch RLS.
- `db/migrations/012_technician_execution.sql` persists the assignment projection, versioned execution state, immutable status/checklist/evidence/override/scan evidence, pending-independent-QC outbox, and idempotency receipts under forced tenant/branch RLS.
- `db/migrations/013_inventory_ledger.sql` persists warehouse-level authorization, exact item/UOM/lot/roll balances, deferred-balanced append-only ledger batches, evidenced transfer/discrepancy state, blind count/recount/investigation/approval evidence, atomic stock reservation, and fingerprinted idempotency under forced tenant/branch/warehouse RLS.
- `db/migrations/014_procurement_workflow.sql` persists tenant-keyed supplier and procurement masters, versioned requisition/PO lines, approvals, exact GRN/return values and evidence, serialized S13 postings, append-only financial/history records, and fingerprinted idempotency under forced tenant/branch/warehouse RLS.
- `db/migrations/015_job_material_control.sql` persists exact Job material demand/outcomes, maker-checker approvals, authorized stock reasons, verified returns, the conservation equation, immutable events/evidence, S13 posting delegates, and fingerprinted idempotency under forced tenant/branch/warehouse RLS.
- `db/migrations/016_qc_rework.sql` persists dual readiness signals, item-level inspection/evidence, blocking rework history, maker-checker emergency overrides, serialized unique effects, and fingerprinted command receipts under forced tenant/branch RLS.
- `db/migrations/017_warranty_incidents.sql` persists immutable delivered warranty terms and linked comeback work, custody escalation/resolution/acknowledgement evidence, durable release events, independently released legal holds, hold-aware retention guards, and idempotent commands under forced tenant/branch RLS.
- `db/migrations/018_native_invoicing.sql` persists billing-readiness projections, exact payer invoices/lines, active payer registration, immutable private documents, maker-checker corrections, serialized fiscal allocation, unique outbox effects, and fingerprinted commands under forced tenant/branch RLS.
- `db/migrations/019_tally_connector.sql` persists exact Tally-authoritative exchanges, unique voucher acknowledgements, immutable file/reconciliation/replay evidence, stable durable delivery effects, serialized acknowledgement import, and fingerprinted commands under forced tenant/branch RLS.
- `db/migrations/020_payments_settlements.sql` persists exact append-only payment/liability events, raw verified Cashfree evidence, credit and correction approvals, settlements, serialized invoice allocation, unique worker effects, and fingerprinted commands under forced tenant/branch RLS.
- `db/migrations/021_delivery_gate.sql` persists private delivery/document evidence, digest-only expiring/revocable QR tokens, scoped never-reused fiscal gate-pass sequences, controlled overrides, an atomic locked gate release, append-only closure history, fingerprinted commands, and forced tenant/branch RLS.
- `db/migrations/022_management_reporting.sql` persists versioned report definitions, exact immutable facts, private export artifacts/manifests, audit and command receipts, plus unique safely claimed worker effects under forced tenant/branch RLS.
- `infra/template.yaml` declares the private object bucket, durable queue/dead-letter queue, API, and worker boundaries. It is an un-deployed deployment artifact; credentials and an explicitly authorized AWS deployment remain external prerequisites.

## Representative Tally support matrix

| Contract generation | Local adapter ID | Certification state |
| --- | --- | --- |
| Current | `TALLYPRIME_CURRENT_REPRESENTATIVE` | Deterministic contract green; exact release mapping and representative installation certification pending |
| One prior | `TALLYPRIME_PRIOR_1_REPRESENTATIVE` | Deterministic contract green; exact release mapping and representative installation certification pending |
| Two prior | `TALLYPRIME_PRIOR_2_REPRESENTATIVE` | Deterministic contract green; exact release mapping and representative installation certification pending |

The matrix deliberately names generations rather than making an unsupported vendor-version claim. Exact TallyPrime releases must be frozen at certification time and exercised with authorized representative installations, credentials, ledgers, tax mappings, direct transport, and controlled export/import files before production enablement.

Run `npm run test:production` and `npm run test:production:typecheck` from the repository root.
