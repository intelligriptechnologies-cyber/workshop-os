# 24 - PostgreSQL schema design

Design proposal, 2026-10-21. No DDL was executed. Recommended budget: **106 tables including alembic_version (105 application/support tables)**: retain 74 candidate tables, add 26 source-entity tables where the candidate has no faithful operational equivalent, and six support tables. This is a preservation-first proposal, not an approved final count. Consolidating legacy history into a common event model is an alternative only after proving every existing query and relationship; archive-only JSON is not an adequate replacement for currently queried history.

No unnamed placeholder table is included in 106.

## SCH-02 - Shared policies and overrides

- Retain candidate bigint business keys and UUID tenant/auth/department keys. Preserve source integer IDs when collision-free; UUID identities use stable audited mappings. Do not renumber existing target rows. UI projections resolve the source ID map; newly created records receive safe integer IDs. Reject IDs outside JavaScript safe-integer range until the adapter has an explicitly reviewed string-ID contract.
- Every new business table has tenant_id uuid NOT NULL REFERENCES tenants(id), branch_id uuid NOT NULL REFERENCES branches(id), and version bigint NOT NULL DEFAULT 1. Existing mutable business tables gain version bigint NOT NULL DEFAULT 1 where absent. The server supplies scope; RLS is enabled and forced. Require composite unique keys on scoped parents and composite FKs on same-tenant/branch business references; global identity references additionally require trusted membership checks. Never accept a client tenant field as scope.
- New id keys are bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY unless the per-table source key is composite. Composite source keys become PRIMARY KEY(tenant_id,branch_id,<mapped source key columns>). Existing keys remain as catalogued. Each branch is constrained to its tenant. Index every referencing FK as (tenant_id,branch_id,foreign_key) unless an existing left-prefix index covers it. Add (tenant_id,branch_id,created_at,id) to chronological lists where these columns exist. Text-search optimization follows measured queries; no new search framework is required.
- New FK delete/update policy is RESTRICT / NO ACTION, deferrable initially deferred for cyclic imported references only. Business deletes follow existing archive/void operations. Do not cascade financial, stock, job or audit history. Existing candidate CASCADE definitions in the appendix are current evidence, not approval: change business-history cascades to RESTRICT in M3-06; membership/session join cleanup may retain explicit cascade after security review.
- Reproduce source unique constraints within tenant/branch, including predicates and case semantics. Do not introduce case-insensitive uniqueness or active-only uniqueness where source uniqueness includes archives without approval. Composite job/parent checks prevent an invoice line/material reference crossing jobs even within one branch.
- Preserve raw decimal quantities/rates/totals with unconstrained numeric where source precision exceeds candidate numeric(p,s). No rounding on import. Keep original financial header numeric fields alongside existing paise fields; native paise is a lossless derived representation only when conversion is exact. Historical subtotal need not equal line sum. New commands must enforce approved arithmetic, not a historical equality CHECK.
- Source date/time text is retained in source provenance. Existing typed timestamps/dates receive a value only under an approved format/timezone rule; no guessing missing timezone. New source-only date/time columns remain text at this preservation stage with service validation. A later typed projection is allowed only with round-trip proof. Defaults shown for new columns preserve source defaults; SQLite datetime('now') must be translated to an equivalent server expression, never copied as executable PostgreSQL syntax.
- Source INTEGER flags in additive columns remain integer with CHECK IN (0,1) where the source contract is boolean; the adapter preserves original 0/1 shape. Existing boolean fields use explicit 0/1 conversion. Null and empty string remain distinct. JSON-like source text (damage marks, detail) is not silently parsed/reformatted; validated projections can coexist.
- Existing native mandatory fields absent from SQLite (actors, financial artifact, line tax allocation, reservation/claim semantics) require explicit mapping. Add origin_kind text NOT NULL DEFAULT 'native' to imported aggregate/history tables. Allow native-only issued_document_id/receipt_document_id and line-derived paise allocation fields to be NULL for origin_kind='imported-unresolved'; CHECK requires them for new native issuance. Never manufacture a PDF, user, approval or tax allocation. Financial UI reads preserved fields until FIN-01 is resolved. Candidate services must be adapted to this nullability before import.
- Source users map to workshop_user_profiles, plus platform_users/tenant_memberships/tenant_roles/membership_roles. Add platform_user_id uuid NULL REFERENCES platform_users(id) to profiles, UNIQUE(tenant_id,id) and UNIQUE(tenant_id,platform_user_id) where non-null. Profile role is the preserved UI code; authorized roles derive from memberships and must be synchronized transactionally. Plaintext password is excluded from operational rows; retain the original sealed source and report this explicit credential disposition. Provision credentials separately.
- Source receipts/gate passes/events/status/movements use named legacy tables because their source rows do not prove the candidate immutable document/event contract. They are operationally queryable, not discarded. New issuance should link them or equivalent compatibility projections to native artifacts in the same transaction; do not maintain two independently writable ledgers. Add native_document_id bigint NULL to legacy_receipts/legacy_gate_passes with a unique scoped FK. New material_requests stores demand; material_reservations stores actual reservations. Add material_requests.reservation_id bigint NULL FK material_reservations and enforce one active reservation linkage per demand where applicable.
- Source stock_qty is a preserved opening/current snapshot, not an additional stock movement. Reconciliation chooses the approved opening-balance convention before new ledger posting. Never seed both the full stock_qty and the same historical ledger deltas as additive stock.

## SCH-03 - Migration order (proposed new revisions, not existing IDs)

M3-01 verifies pinned candidate fresh replay and separately designs the old-checkout lineage bridge; never stamp over rewritten history. M3-02 adds provenance, profiles and scope foundations. M3-03 adds missing source business tables, exact columns and nullable import accommodation. M3-04 adds command receipts/templates/assets/snapshots/outbox. M3-05 adds approved semantic mappings and financial precision fields. M3-06 adds scoped keys/FKs/indexes/RLS after exception resolution. M3-07 validates constraints and grants after disposable reconciliation. Backward-compatible expand steps precede adapter cutover; no destructive contract/drop step is approved. Cycles (booking/visit/job, material/invoice claim, documents) are loaded in two passes within the isolated import transaction, then constraints checked before commit.
