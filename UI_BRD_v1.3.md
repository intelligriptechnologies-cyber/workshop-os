## 3. Job status model — required changes

Current model (`src/types.ts:3-21`):

```
MainStatus = "NEW" | "IN_PROGRESS" | "COMPLETED" | "CLOSED"
SubStatus  = 16 values (Gather Requirements, Create Estimate, Get Confirmation,
             Material Requested, Material Issued, Washing Needed, Work Started,
             Follow-up Needed, Photos Shared, QC Pending, Customer Verification,
             Invoice Ready, Payment Received, Receipt Generated,
             Gate Pass Generated, Delivered)
```

**Verified: the 16 existing `SubStatus` values already cover every sub-step described in your notes** (Gather Requirements → Create Estimate → Get Confirmation on NEW; Washing Needed / Follow-up Needed / Photos Shared on IN_PROGRESS; Customer Verification / Invoice Ready / Payment Received on COMPLETED; Receipt Generated / Gate Pass Generated on CLOSED). **No change needed to `SubStatus`.**

**Required change to `MainStatus`:** add `"HOLD"` and `"CANCELLED"`.

```
MainStatus = "NEW" | "IN_PROGRESS" | "COMPLETED" | "CLOSED" | "HOLD" | "CANCELLED"
```

Transition graph, from your notes:

```
NEW ─────────────→ IN_PROGRESS ─────────────→ COMPLETED
                                                   │  │
                                          ┌────────┘  └────────┐
                                          ▼                    ▼
                                        HOLD                 CLOSED
                                       │    ▲            (terminal; Gate Pass
                                       ▼    │             + payment receipt
                                   CANCELLED│              generated here)
                                       │    │
                                       └────┘
                                    (REOPEN → IN_PROGRESS)
```
- COMPLETED → HOLD or CLOSED
- HOLD → IN_PROGRESS or CANCELLED
- CANCELLED → (REOPEN) → IN_PROGRESS
- Edit Job locks the customer and vehicle fields once a job exists; every other field (status, work list, notes, assignments) stays editable until CLOSED.
- Add/edit is possible on the job at any point before CLOSED.

**Breaking-ish changes this requires, called out explicitly so they aren't a surprise mid-build:**

1. `validateLargeDemoDataset` (`src/db.ts:190-216`) hard-asserts `count(distinct main_status) = 4` and `count(distinct sub_status) = 16`. Once HOLD/CANCELLED exist in the large demo dataset, this becomes `= 6` and stays `= 16`. Update the assertion and the generated dataset together, or "Load Large Demo Dataset" breaks.
2. `cancelJobCard()` (`src/db.ts:423-428`) today **archives** the job (soft-delete, removes it from active views) — it is not a `CANCELLED` main-status transition. Reconcile this: either repurpose `cancelJobCard` to set `main_status = "CANCELLED"` (keeping the job visible, reopenable) and use a separate archive action for true removal, or add a new `setJobStatus` transition function and leave `cancelJobCard` for admin-only hard archive. Recommend the former to match "from CANCELLED it can be REOPEN."
3. `updateJobCard`'s automatic history note (`src/db.ts:420`, hardcoded `"Job card updated"`) should accept a free-text note/comment parameter so "SAVE NOTES for each step" (your requirement) is an actual user-entered comment, not a fixed string. `history()` (`src/db.ts:915`) already has the right shape (main, sub, note per change) — extend its caller, not the function itself.

## 4. Job Card lifecycle — UI behavior

(Canonical statement — referenced from both §5.2 Jobs and §5.6 Manage ▸ Visits/Jobs, not repeated.)

- On **NEW**: add/confirm customer and vehicle, record complaint/issue, gather requirements, create estimate, get confirmation.
- On **IN_PROGRESS**: work execution, follow-up/communication, share photos, mark washing needed; estimate can still be created/edited and downloaded as PDF/shared.
- On **COMPLETED**: customer verification, generate invoice, receive payment. Add/edit remains possible up to this point.
- On **CLOSED**: generate gate pass and payment receipt for vehicle release. Terminal state.
- **HOLD**: reachable from COMPLETED; returns to IN_PROGRESS or advances to CANCELLED.
- **CANCELLED**: reachable from HOLD; REOPEN transition returns it to IN_PROGRESS.
- Every status change captures a note/comment (free text) tied to that transition, visible in the job's History tab (§5.6) and in the equivalent record shown to other roles' respective queues (e.g. Service Advisor's My Queue reflects the same history).
- Edit Job locks customer and vehicle once the job exists; other fields remain editable per the state rules above.
